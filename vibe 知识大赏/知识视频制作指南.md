# 「Vibe 知识大赏」知识视频制作指南

> 写给 AI 的说明文档。开始做新视频前，请先完整读一遍，再按「制作流程」执行。
> 参考成片：《从深度学习到 GPT · 大模型简史》，共 3:28、25 个镜头、9 章。源码在 `output/build_history/`。

---

## 1. 这是什么样的视频

- **风格**：黑金纪录片风格的动态信息图。深色底、金色强调、衬线字体，没有旁白，靠一行字幕、动画和背景音乐讲完一件事。
- **形态**：先做成一个单文件 HTML 网页版视频，可以自动播放、拖动进度、按 S 打开出处抽屉。再用脚本逐帧录成 MP4，用于发布。
- **时长**：3 分钟左右最合适。用户明确反馈过：5 分钟太长、节奏慢；3 分钟左右正好。
- **选题**：面向普通观众，要让人看得懂。用户反馈过：源码级的硬核选题（比如 DeepInfer 推理引擎）做出来很多人看不懂；「发展历程 / 一个概念的来龙去脉」这类选题效果最好。

## 3. 工程结构（直接复制 `output/build_history/` 改内容）

```
build_history/
├── data.js           # ★ 唯一的内容源：章节、镜头、字幕、角标、出处、核查备注（HTML 和分镜稿都由它生成）
├── visuals_shots.js  # ★ 每个镜头的画面函数 VIS[名字](c, p)
├── visuals_base.js   # 绘图工具：T 文字、RR 圆角框、LN 线、ARROW、DOT、TYPE 打字机、缓动 ez/eo/sg/so 等
├── engine.js         # 播放引擎：时间轴、交叉淡化、字幕、角标、进度条、出处抽屉、背景音乐避让
├── style.css / template.html
├── build.mjs         # 构建：内联全部内容和背景音乐 → 单文件 HTML + 分镜脚本.md，并打印总时长
├── render_video.cjs  # 把 HTML 逐帧录成 MP4（1080p、30fps、带背景音乐）
└── tools/            # 截图自查脚本 shot.cjs / shot2.cjs / sheet.cjs 和依赖清单 package.json
```

### 环境准备（新会话里 /tmp/pw 不存在时执行）
```bash
mkdir -p /tmp/pw && cp output/build_history/tools/* /tmp/pw/ && cd /tmp/pw && npm i
npx playwright-core install chromium-headless-shell   # 已有 ~/.cache/ms-playwright/chromium_headless_shell-* 就跳过
```

### 关键约定
- **镜头数据**（data.js）：
  `{ id, ch, vis, big, small, en, zh, desc, subs: [...], refs: [{t,u}], note, hold?, noSub?, reversal?, cut? }`
  - `subs` 中用【】包裹的词显示为金色关键词。
  - **每句字幕的时长自动计算**：`max(1.6, 字数×0.15+0.4)` 秒。改字幕会直接改变节奏。
  - `reversal: 1` 表示反转镜头：画面边缘泛红光，背景音乐压低。
  - `cut: 1` 表示暂时剪掉这个镜头，不用删数据。
- **画面函数**：`VIS.xxx = function (c, p) {...}`，其中 `p = {t, d, L(k)}`。`L(k)` 是第 k 句字幕出现的时刻，**动画要和字幕句对齐**，例如 `so(t, L(2), L(2)+0.6)` 表示第 3 句出现时淡入。
- **画面是 t 的纯函数**：不能用 `Date.now()` 或随机数，随机请用 `rnd(seed)`。这样才能任意拖动，也才能逐帧录成视频。
- **画布与安全区**：画布 1920×1080；内容放在 y < 900 的范围内，下方留给字幕。
- **配色**：`G #C9A35B` 金、`GL #E6C987` 亮金、`W #ECE4D4` 米白、`GR #8C8577` 灰、`DG #3A352D` 暗灰、`R #B5473A` 警示红、`BL #5E7F9E` 冷蓝。
- **叙事结构**：钩子（结果先行，例如「两个月破 1 亿」）→ 按时间分章 → 一处反转（「越大越好用？错」）→ 收束到「你在这里」→ 片尾年份串联。

## 4. 制作流程

1. **定选题和角度**：只问会改变做法的问题（主题、时长、面向谁）。用户已经说清楚的不要再问。
2. **写分镜**：直接写 `data.js`。每个镜头写清楚 desc（画面怎么动）、subs（字幕）、refs（论文或官方出处）、note（核查备注）。
   - **每个数字和日期都要核查**，附上可点开的出处链接。查不到原文的标「待确认」，交付时告诉用户。
3. **写画面**：在 `visuals_shots.js` 里为每个 `vis` 写函数，优先复用已有镜头的写法（时间线、对比圆、聊天窗、流程图、坐标图、卡片阵列、印章等）。
4. **构建**：`node build.mjs`，输出 HTML、分镜脚本.md 和总时长。时长超出目标时，删减或合并镜头，或者精简字幕。
5. **截图自查（必须做）**：
   ```bash
   cd /tmp/pw && node shot.cjs <html绝对路径> /tmp/shots [镜头id,...]          # 每个镜头截 55% 和 92% 两个时刻
   FR=0.15,0.35 node shot2.cjs <html> /tmp/shots [ids]                         # 指定截图时刻（镜头时长的比例）
   node sheet.cjs /tmp/shots /tmp/sheets '[]'                                  # 拼成联系表，再用 Read 查看
   ```
   重点检查：文字重叠、元素压住字幕、画面空白太久、上一个镜头的残影、标签离开了它标注的对象、浏览器控制台报错（输出里 `errors: []` 才算正常）。
6. **交付网页版**：把 HTML 发布成可访问的产物（用所在环境的产物发布命令，如 `publish-artifact <html绝对路径>`）；分镜脚本 md 也一起发布。
7. **录成 MP4**（用户要发布时）：
   ```bash
   cd output/build_history
   node render_video.cjs ../xxx.html ../xxx.mp4                       # 全片，4 路并行，约 3 分钟片长录 30~40 分钟，放后台跑
   node render_video.cjs ../xxx.html /tmp/t.mp4 --from 60 --to 70     # 先录一小段检查
   ```
   - 录制时会注入 Noto Serif SC 字体、关闭 CSS 过渡，背景音乐按网页逻辑做避让和首尾淡入淡出。
   - 编码参数为 x264 `crf 25 preset slow`。画面有颗粒噪点，crf 18 会让文件膨胀到 1GB 以上；crf 25 时文字依然清晰，3 分半约几十 MB。
   - 验收：用 ffprobe 核对时长和音轨，再抽几帧看画面。声音 AI 听不到，交付时提醒用户自己听一遍。

## 5. 用户偏好与经验

- 先给结论和成品，再说明改了什么、哪些内容待确认，并主动提供压缩时长的方案。
- 用户喜欢「发展历程」类的叙事，愿意不断补充新章节（例如后来加的「七 · 行动」Agent 章）。新增内容后要同步更新：结尾时间轴、「你在这里」镜头、片尾年份、分镜稿主线。
- 时效性内容按「今天」的日期写（「今年」指当前年份），避免说法过时。
- 所有交付物放在 `output/`，并用所在环境的产物发布命令发布。
